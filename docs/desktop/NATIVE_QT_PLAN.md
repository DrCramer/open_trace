# OpenTrace Desktop — нативный интерфейс Qt 6 (без браузерного движка)

Решение пользователя (07.11.2026): desktop-приложение не должно быть веб-страницей в WebView; интерфейс
переносится на **Qt 6 Widgets**, связка с Rust — **cxx-qt / CXX**. Ветка `feature/native-qt-desktop`.
WebView-версия (`desktop/opentrace-desktop`, Tauri) остаётся рабочей, пока нативная не догонит её по функциям.

> Исследовательское ПО: не валидировано для диагностического или судебно-экспертного применения.

## Архитектура

```
 Qt 6 Widgets (C++, desktop/opentrace-qt/cpp)      ← окна, меню, таблицы, диалоги, QPainter-графики, печать
        │  CXX-мост (src/bridge.rs, cxx-qt-build: moc, Qt-линковка)
 Rust: состояние проекта и оркестрация (src/backend.rs) ← то, что сейчас делает JS: проект, библиотеки, порядок анализа
        │  прямые вызовы в процессе (без HTTP)
 opentrace-core (Rust)                               ← все алгоритмы: чтение FSA/HID, калибровка, пики, генотипы, QC
```

* Никакого браузерного движка: системное меню окна (QMenuBar), QToolBar, QTableView, QFileDialog, QPrintDialog,
  QPdfWriter (векторный PDF), стиль платформы (Windows 11 / Fusion на Linux).
* Ядро вызывается теми же функциями, что обслуживают HTTP-API (`server::analyze_request` = `POST /api/analyze`,
  `analysis_method::method_request` = `/api/analysis-method`): нативный и веб-интерфейсы анализируют одинаково,
  эталонные тесты ядра продолжают проверять обе дороги.
* Логика, которая сейчас живёт в JavaScript (около 880 КБ), переносится **в Rust**, не в C++: C++ только показывает.
  Это даёт модульные тесты без GUI и общий код для desktop и сервера.

## Этапы

1. **Каркас и вертикальный срез (сделано в первом коммите):** главное окно (меню Файл/Правка/Анализ/Вид/Графики/
   Инструменты/Справка, панель, навигатор, таблица образцов с SQ, сведения), добавление FSA/HID с выбором метода и
   стандарта длин, импорт метода и стандарта длин из XML GeneMapper, анализ ядром в несколько потоков с прогрессом и
   остановкой, окно графиков (красители, масштаб протяжкой/Ctrl+колесо, п.н./точки, число панелей), печать и
   векторный PDF с датой 24 ч, самотест для CI.
   **Сделано дальше (этапы 2–3, первая часть):** Менеджер панелей (импорт панелей/бинов/статтеров GeneMapper,
   хранение как в `kits.js` и тот же генератор текстов), Параметры проекта (сводка лестниц, смещение бинов,
   минимальные высоты вызова, pull-up), генотипирование как в веб-версии (`src/genotype.rs`: группы папка+панель,
   оценка лестниц, смещения бинов, сводка аллельных лестниц, контроли, GQ/CGQ, метки лестниц), колонки SOS/SQ/SSPK/CGQ,
   тип образца и панель, вкладка «Генотипы». **Приёмка выполнена:** 14 файлов PGplus — таблица вызовов нативной версии
   побайтно совпадает с веб-версией (3437 вызовов); выдуманные файлы ядра — 120/120 маркеров как заложено (CI).
2. **Библиотеки:** Panel Manager (импорт панелей/бинов/статтеров GeneMapper), методы анализа (редактор), стандарты
   длин, Project Options; хранение в каталоге данных пользователя (сейчас в WebView — localStorage).
3. **Генотипирование как в веб-версии:** группы папка+панель, оценка лестниц, смещения бинов, вызовы аллелей,
   PQV (SOS, SSPK, MIX, OMR, CGQ, GQ…), вкладки Сводка/Генотипы, сохранение/открытие проектов (формат веб-версии).
   Приёмка: для одного набора FSA таблицы генотипов нативной и веб-версии совпадают побайтно (сравнение в CI).
4. **Окно графиков полностью:** заголовки маркеров/GQ, бины, метки аллелей (2–4 ряда), таблицы Sizing/Genotypes,
   правка меток (добавить/удалить/переименовать, артефакты, журнал, отмена), Plot Settings, печать как в ID-X.
5. **Таблицы и отчёты:** Table Settings, экспорт, Report Manager, печать/предпросмотр.
6. **Остальные инструменты:** профили и сравнение, CODIS, смеси, матрицы, безопасность/аудит/эл. подпись.
7. **Desktop-сервисы и поставка:** сервер организации, синхронизация FSA, черновики, лабораторный профиль,
   происхождение анализов; установщики Windows (MSI/NSIS с Qt-библиотеками) и Linux; затем WebView-версия
   выводится из поставки.

Оценка: этапы 2–4 — несколько недель каждый, полный паритет — месяцы. Каждое окно сверяется с веб-версией и
ID-X по `UI_COMMAND_INVENTORY.md`.

## Сборка

* Linux: `sudo apt install qt6-base-dev qt6-base-dev-tools`, затем
  `QMAKE=/usr/bin/qmake6 cargo build --release --manifest-path desktop/opentrace-qt/Cargo.toml`.
* Windows: Qt 6.8 (MSVC 2022 x64), `QMAKE=<Qt>\bin\qmake.exe cargo build --release ...`, затем `windeployqt` и папка
  `resources` рядом с exe (так собирает CI: артефакт `opentrace-qt-windows`).
* Самотест: `QT_QPA_PLATFORM=offscreen OT_QT_AUTOTEST_FILES=synthetic:5 OT_QT_AUTOTEST_OUT=<dir> opentrace-qt` —
  выдуманные файлы ядра → анализ → `main.png`, `plot.png`, `plots.pdf`, `result.json`.

## Лицензирование Qt

Qt 6 используется по LGPLv3 (динамическая линковка с библиотеками Qt, поставляемыми рядом с exe, без изменения Qt) —
это совместимо с открытым кодом OpenTrace. Перед публичной поставкой нужна проверка условий LGPL (тексты лицензий
в поставке, возможность замены библиотек Qt пользователем).
