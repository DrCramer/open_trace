## Этапы

### C — Server v1 и блокировка ✅
Сделано: SQLite + миграции, контентное хранилище FSA, API v1, единые пользователи, lease/fencing/ревизии, read-only, WEB не обходит блокировку, резервные копии. **ProjectWorkspace в десктопе**: источник проектов «сервер», открытие на редактирование или только чтение («Проект редактирует …»), heartbeat 25 с, сохранение с ревизией и fencing-токеном, FSA по `sha256`, потеря lease → только чтение, освобождение при закрытии.
Дальше: WEB-клиент — захват lease при открытии (сейчас сервер просто отклоняет его запись при чужой lease); локальный черновик при потере lease.

### D — Единые стандарты 🟡
Сделано: на сервере версии, жизненный цикл, четыре глаза, неизменяемость (код + триггеры), профили с закреплёнными хешами, provenance; в десктопе экран «Лабораторные стандарты» (список, импорт локальных справочников как черновиков с проверкой хешей, отправка, утверждение, профили); каноническая сериализация и SHA-256 у клиента и сервера совпадают (тест).

## Риски

| Риск | Влияние | Мера |
|---|---|---|
| W6: 1 ULP между Windows и Linux | устранено для exp/log/pow | `libm_port` + отпечаток в тестах обеих ОС; `expm1`/`sin` ещё системные; `math_backend` в самотесте и `version` |
| W7/W7c: регистр и недопустимые символы в id образцов на NTFS | раньше — тихая потеря образца | теперь отказ с сообщением; полная поддержка — кодирование имён файлов (формат проекта, решать вместе с миграцией) |
| Служба Windows не проверена под SCM | возможна ошибка прав виртуальной учётной записи | проверить `service-install` на тестовом сервере до внедрения; запасной вариант — задача планировщика |
| WebKitGTK: тело custom-scheme запроса | падение на Blob, возможное усечение | ArrayBuffer + проверка длины (`X-OT-Body-Length`) |
| WebView2: `initialization_script` в окнах `SetNewWindow` | скрипты десктопа не выполнялись | скрипты вставляются в HTML |
| `MAX_JSON_BYTES` = 1 ГиБ, base64 FSA в сохранении проекта | память | десктоп в режиме сервера передаёт FSA отдельно по `sha256`; WEB-путь пока base64 |
| Учётные данные по умолчанию без паролей | вход невозможен до `set-password` | инструкция; API v1 отказывает пользователям без пароля |
