## Этапы

### A — Аудит и окружение ✅
Worktree и ветка, upstream снят (`git push` не уйдёт в исходную ветку). Аудит (`BASELINE_AUDIT.md`), архитектура, матрица ID-X, Windows-несовместимости W1–W7, CI-заготовка.

### B — Первая работающая Desktop-сборка ✅ (без установщика в этой итерации)
Tauri 2, существующий UI через схему `opentrace://` с ядром в процессе, нативные окна с `window.opener`, кэш и очередь FSA, подключение к серверу, самотест. Осталось: проверить установщики, иконки/подписи, локализацию системных диалогов.

### C — Server v1 и блокировка ✅ сервер / 🟡 клиент
Сделано: SQLite + миграции, контентное хранилище FSA, API v1, единые пользователи, lease/fencing/ревизии, read-only, WEB не обходит блокировку, резервные копии.
Дальше (C2, приоритет 1): **ProjectWorkspace в десктопе** — «Открыть проект с сервера» (только чтение / редактирование), heartbeat lease, сохранение через `/api/v1/projects/{name}/idx` с `fsa_sha256`, понятные сообщения «Проект редактирует …», потеря lease → только чтение, черновик отдельно. Плюс WEB-клиент: захват lease при открытии на редактирование.

### D — Единые стандарты 🟡
Сделано на сервере: версии, жизненный цикл, четыре глаза, неизменяемость (код + триггеры), профили с закреплёнными хешами, provenance.
Дальше (приоритет 2): экран «Лабораторные стандарты» (список, черновик, отправка, утверждение, сравнение версий); импорт `localStorage`-справочников (`opentrace.methods.v1`, `opentrace.kits.v1`, `opentrace.sizestd.v1`, матрицы) как черновиков с проверкой конфликтов имён/хешей; выбор утверждённого профиля при «Добавить образцы»; запись provenance после анализа; локальный проверяемый кэш утверждённых версий (по SHA-256).

### E — Массовый FSA и графики 🟡
Сделано: бинарная передача, дедупликация, ограниченная очередь, кэш с лимитом, пул анализа.
