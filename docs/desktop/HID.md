# Файлы `.hid` (GeneMapper ID-X)

OpenTrace читает файлы `.hid` так же, как `.fsa`: «Добавить образцы» принимает `.fsa`, `.ab1` и `.hid`; анализ, окно
графиков, таблицы и проекты работают одинаково. Исследовательское ПО: не валидировано для диагностики и судебно-
экспертной работы.

## Формат

`.hid` — ABIF версии 3 (`version = 300`) вместо версии 1 у `.fsa`. Каталог тот же (записи по 28 байт), но у типов
27…35 старшие 16 бит последних четырёх байт записи задают кодирование содержимого (по декомпиляции ID-X 1.6,
`com.apldbio.shared.ABIF`):

| режим | содержимое |
|---|---|
| 0 | как есть |
| 1–3 | zlib |
| 4 | gzip |
| 5 | DES-CBC, PKCS#5 (трассы `DATA`, имена красителей `DyeN` и др.) |

Типы 27…35 после декодирования соответствуют обычным типам ABIF: 27→1, 28→4 (short), 29/30/33→2, 31→5 (int; например
`OvrV`/`OvrI`), 32→8, 34→2 (строка — всё содержимое), 35→7 (float). Реализация: `core/opentrace-core/src/hid.rs`,
разбор каталога — `abif.rs`.

## Ключ

Параметры DES **не входят в OpenTrace** и не хранятся в репозитории. Они читаются во время работы из `GMp.jar`
лицензионной установки GeneMapper ID-X 1.6 пользователя (класс `com/apldbio/shared/ABIF/a/a.class`: сериализованный
`KeyRep` DES и вектор инициализации — литералы конструктора). Ключ не пишется в журналы и не отдаётся по API:
`GET /api/hid-codec` сообщает только, доступно ли чтение и из какого файла.

Где ищется `GMp.jar` (по порядку):

1. путь из настроек: Desktop — окно «Сервер организации» → «Файлы HID (GeneMapper ID-X)» (кнопка «Обзор…», путь
   проверяется сразу и сохраняется в `desktop.json` как `idx_gmp_jar`); Server — `idx_gmp_jar = "…"` в
   `server.toml` или `OPENTRACE_SERVER_IDX_GMP_JAR`;
2. переменная окружения `OPENTRACE_IDX_GMP_JAR` (также для `opentrace serve`);
3. Windows: `C:\`, `D:\`, `E:\AppliedBiosystems\GeneMapperID-X\app\GMp.jar`.

Без ключа `.hid` не анализируется: образец помечается ошибкой «HID data is encrypted; reading it needs the GeneMapper
ID-X 1.6 installation (GMp.jar)…», остальные образцы анализируются.

## Повреждённые записи

Записи, которые ID-X не использует для анализа (например, `AsyC` — описание анализа), при ошибке расшифровки
остаются непрозрачными байтами. Ошибка в `DATA` или `DyeN` — ошибка файла: образец пропускается с сообщением, анализ
остальных продолжается.

## Проверка

- `cargo test --lib hid` (ядро): DES-CBC, извлечение литералов из байткода, синтетический `.hid` (FSA из тестовых
  данных, перекодированный в v3 с тестовым ключом) даёт те же каналы, что исходный FSA.
- `tests/hid_local.rs` — на настоящих файлах, только локально: `OPENTRACE_TEST_HID_DIR=<папка с .hid>
  OPENTRACE_IDX_GMP_JAR=<GMp.jar> cargo test --test hid_local -- --nocapture`. Настоящие `.hid` и `GMp.jar` в Git не
  добавляются.
- Проверено 6.11.2026 на наборе заказчика (GlobalFiler, 3500, 6 красителей, 9641 скан): 7 из 8 файлов читаются,
  анализируются с набором `GlobalFiler_Panel_v1.1.1X` и стандартом GS600 LIZ, окно графиков показывает локусы и бины.
  В одном файле записи начиная примерно с 610 КБ (`DATA5…8`, `DATA106`, …) не расшифровываются — файл, по-видимому,
  повреждён; он пропускается с ошибкой `DATA5: wrong HID key or corrupt payload`. Как его открывает сам ID-X, не
  проверялось.

Не сделано: запись `.hid` (OpenTrace только читает), сравнение результатов анализа `.hid` с ID-X на тех же файлах.
