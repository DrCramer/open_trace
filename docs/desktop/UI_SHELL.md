# OpenTrace Desktop — настраиваемая промышленная оболочка интерфейса (v10.4)

Ветка `feature/desktop-configurable-industrial-ui`. Реестр всех команд и элементов с ID — `UI_COMMAND_INVENTORY.md`.

> Исследовательское ПО: не валидировано для диагностического или судебно-экспертного применения. Оболочка меняет только
> вид и способы вызова команд. Алгоритмы анализа FSA, калибровки, детекции пиков, генотипирования, API ядра/сервера,
> форматы проектов и лабораторных стандартов не изменялись.

## Что видит пользователь

* **Одна строка меню.** Слева разделы меню окна (в главном окне: Файл, Правка, Анализ, Вид, Графики, Инструменты,
  Администрирование, [Сервер — только desktop], Справка). Справа закреплена группа: статус «Редактирование / Только чтение /
  Локально / Нет проекта» (не скрывается), «Команды» (Ctrl+Shift+P), лабораторный профиль (desktop), выбор темы,
  ⚙ быстрые настройки (не скрывается), ◐ светлая/тёмная, пользователь. При узкой ширине меню прокручивается под
  закреплённой группой, у кнопок исчезают подписи.
* **Вторая строка — рабочие области:** Проекты | Графики | Генотипы | Стандарты | Журнал. «Проекты» — прежние вкладки
  Образцы, Сводка анализа, Информация, Raw Data, EPT; «Генотипы» — прежняя вкладка; «Графики», «Стандарты», «Журнал» —
  страницы со списком существующих команд этой области (те же обработчики, что и пункты меню).
* **Компактные панели инструментов** и строка состояния без отступа снизу.
* **Окна графиков, Менеджер панелей, Менеджер отчётов** — та же оболочка (строка меню + правая группа, тема, палитра,
  настройка интерфейса). Состав их меню и кнопок не менялся.
* **Классический вид** (как ID-X) остаётся: ⚙ → «Вид окон» → «Классический». В WEB-клиенте он включён по умолчанию,
  в desktop по умолчанию — промышленный вид и графитовая тема.

## Как настроить

* **Вид → Настроить интерфейс…** (или ⚙ → Настроить интерфейс…): слева области (меню каждого раздела и подменю,
  вкладки, панели инструментов, панель правки аллелей, правая группа, строка состояния), справа — элементы области:
  флажок «Показ», ▲/▼ или перетаскивание для порядка, поиск по названию/ID, фильтры «Отображаемые / Скрытые /
  Недоступные сейчас». Внизу: «Заводской интерфейс», «Сбросить эту область», «Экспорт…/Импорт…» (JSON
  `desktop_ui_layout_v1`), «Сохранить как раскладку» (пресет «Пользовательская»), «Применить».
* **Палитра команд** — Ctrl+Shift+P или кнопка «Команды»: поиск по названию, пути меню и ID; Enter выполняет, Esc
  закрывает. Скрытые команды в палитре остаются.
* **Пресеты** (⚙ → Раскладка рабочего места): Стандартная, Анализ, Ручная интерпретация, Контроль качества, Два
  монитора, Пользовательская. Пресет задаёт видимость элементов и один раз — подсказки окнам (навигатор, «низкое
  качество наверх», таблица и число панелей окна графиков). Выбор пресета заменяет текущую видимость: свою раскладку
  сначала сохраните как «Пользовательскую».
* **Аварийный сброс** — Ctrl+Shift+F12 (или Вид → Восстановить интерфейс): заводская раскладка с подтверждением;
  сохранённая «Пользовательская» раскладка не удаляется. Повреждённая или будущая по версии раскладка не применяется:
  открывается заводская и показывается сообщение.
* **Не скрываются никогда** (флажок заблокирован, ID в раскладке игнорируется): статус редактирования/только чтения,
  ⚙, сообщение строки состояния, кнопка «Стоп», сведения о маркере в окне графиков, desktop-ячейки синхронизации FSA и
  блокировки проекта, баннер «только чтение».

## Темы и фон электрофореграмм

Темы оболочки: Системная, Светлая, Графитовая, Тёмная, Контрастная — CSS-токены `--c-*` в `shell.css`, классические
переменные `idx.css` переопределяются только при `data-chrome=industrial`. Переключение без перезагрузки и без повторного
анализа.

Фон графиков — отдельный слой: Авто / Светлый / Тёмный (⚙ → Фон графиков); «Авто» даёт тёмное поле только с тёмной темой,
графитовая тема оставляет светлое поле ID-X. В окне графиков: Вид → Фон графиков (это окно) — своё значение на время
сеанса окна. Палитра красителей (`plotPal()` в `plot.js`): на светлом поле — прежние цвета ID-X; на тёмном — тот же тон
каждого красителя с яркостью для тёмного фона: DATA1 синий, DATA2 зелёный, **DATA3 светлая линия вместо чёрной**,
DATA4 красный, **DATA105 оранжевый, DATA106 фиолетовый (не переставлены)**. **Печать, предварительный просмотр и
векторный PDF всегда идут светлой палитрой ID-X** независимо от темы.

## Хранение

`desktop_ui_layout_v1` (`schema_version: 1`): `chrome`, `theme`, `plot_surface`, `density`, `labels`, `active_preset`,
`hidden{область:[id]}`, `order{область:[id]}`, `custom`, `saved_at`. Desktop: `GET/POST /desktop/api/ui-layout`, файл
`ui_layout.json` рядом с `desktop.json` (атомарная запись, только известные поля, ≤512 КиБ, версия проверяется);
WEB: `localStorage['opentrace.uiLayout.v1']`. Окна одного приложения синхронизируются через `BroadcastChannel`.
Раскладка — пользовательское предпочтение этого компьютера: в ней нет токенов, паролей, методов, панелей, стандартов и
данных проектов, на сервер организации она не отправляется. Новые команды после обновления приложения появляются
показанными на заводском месте; неизвестные ID в раскладке показываются в редакторе с кнопкой «Удалить неизвестные».

## Устройство (для разработчиков)

* `resources/web/idx/shell.js` — реестр, раскладка, темы, палитра, редактор. `buildMenubar` (ui.js) передаёт спецификацию
  меню в `Shell.prepareMenu(win, spec)`: регистрирует `<окно>.menu.<раздел>[.<подменю>]/<id>` и возвращает спецификацию
  с учётом видимости/порядка. Контейнеры с `data-area` (панели, вкладки, статус) обрабатываются `MutationObserver`:
  дети с `data-cmd` регистрируются, скрываются/упорядочиваются; `data-critical` — не скрывается.
* ID пунктов меню — ключи i18n (`id:'displayPlots'`), кнопок — `id` кнопки или имя значка, красителей — `dye.DATA1`…
* `shell.css` — токены тем, промышленная геометрия, палитра/редактор; печать (`@media print`) скрывает оболочку.
* Desktop: `shim.js` публикует `window.__otWsStatus`/`__otLabProfile` и событие `opentrace-ws`;
  `src-tauri/src/uilayout.rs` — хранение раскладки.

## Проверки

* `desktop/opentrace-desktop/tests/e2e/ui_shell.cjs` — 40 проверок в Chromium (см. T1–T8 в реестре): геометрия строки меню,
  вкладки, реестр, палитра, редактор (скрытие, порядок, применение), сохранение после перезагрузки, критичные элементы,
  повреждённая раскладка, Ctrl+Shift+F12, пресеты (в т.ч. в окне графиков), темы, фон графиков (светлое поле с
  графитовой темой, тёмное поле, отсутствие чёрных линий на тёмном поле, синхронизация между окнами), окна Менеджера
  панелей и отчётов, **генотипы до и после всех переключений совпадают**. Запуск в CI (Linux) на встроенном примере;
  локально можно указать `OT_FSA_DIR` с набором FSA (в репозиторий не входит).
* `uilayout.rs` — модульные тесты хранения (известные поля, версия, размер, повреждённый файл).
* `ui_inventory_dump.cjs` + `ui_inventory_md.py` — генерация `UI_COMMAND_INVENTORY.md` из живого реестра.

## NOT VERIFIED (честно)

* Нативные окна Tauri: WebView2 (Windows 10/11, DPI 125/150/200 %, несколько мониторов) и WebKitGTK (Linux) —
  проверено только в Chromium/Playwright на `opentrace serve`; сборка установщика и ручная проверка на Windows — после
  публикации ветки.
* Сочетания Ctrl+Shift+P и Ctrl+Shift+F12 в WebView2/WebKitGTK (перехват системой/браузерным движком).
* Desktop-ветка хранения `/desktop/api/ui-layout` проверена модульными тестами Rust, но не e2e в собранном приложении.
* Контрастная тема — без формальной проверки контраста WCAG; значки панелей в тёмных темах перекрашиваются фильтром
  (инверсия яркости с сохранением тона) — не все значки проверены визуально.
* Полное соответствие ID-X по всем вкладкам редакторов (Plot Settings, Manager) — состав не менялся, но поэлементная
  сверка с ID-X 1.6 в этой работе не проводилась.
